# Exploited Design Context

## Design Register
Product UI. The frontend is intentionally minimal because another teammate owns full frontend direction later.

## Scene
A researcher is moving quickly at a hackathon table, using a laptop in normal indoor lighting, trying to verify whether the demo produces a believable investigation flow before the final presentation.

## Visual Direction
- Restrained product surface with dense, readable panels.
- Clear state and evidence hierarchy before decorative styling.
- Neutral background with a single rust-red accent for exploitation risk and action priority.
- Semantic status colors only for source availability and risk.
- No gradient text, no glassmorphism, no side-stripe cards, no nested card stacks.

## Components
- Standard top navigation and dashboard layout.
- Segmented company/region input.
- Compact score blocks, source status rows, evidence table, benchmark empty state.
- Icon buttons or icon plus label where actions need recognition.
- Panels use 8px or smaller radius.

## Typography
Use a native product font stack for speed, trust, and readability. Keep dashboard typography tighter than a marketing page.

## Motion
Only use short state feedback transitions for hover, focus, loading, and error reveal. Avoid ornamental entrance animation.
